## 从这里开始

本次实施按依赖执行 A–F；R0–R5 继续作为回归覆盖。“可执行”表示遵循现有政策，具体实施由任务指令授权。C1 等待所有者单独决定；C2 与受限 X3 按下表记载的授权执行，X1/X2 需要明确实验预算；延期实验不阻塞其他修复。父计划复审逾期时，扩展范围前报告。

先读 `AGENTS.md`、[STATUS](../STATUS.md) 和工作包指定的领域文档。本文拥有本轮修复顺序，领域文档拥有产品契约，STATUS 拥有仓库优先级。此前本地方案和评审仅作研究参考，不再作为并行执行指令。遇到现有契约冲突，只暂停受影响的变更并提交复核。

成功标准是正确完成或正确等待、不重复副作用、不串作用域，并减少无谓恢复。Main 判断目标、证据充分性和用户接手；runtime 拥有身份、范围、权限、执行事实和持久转换。沿用既有 Run、Plan、证据、effect claim 和 selector；函数组织由实现者判断。

## R0：建立可重建基线

**理由：** 当前检视的工作树混有已跟踪和未跟踪改动，mtime 不能证明作者归属或安装包来源。

1. 若已提供交接快照，核对其 base 和 manifest；否则捕获 HEAD、status、暂存/未暂存 diff 和非忽略未跟踪文件。在跟踪源码之外保留可恢复本地快照，包含必要未跟踪源码、测试和 cassette；记录内容清单与哈希，复查捕获期间是否有并发变化。交接不携带凭据或生产数据库。
2. 在隔离 checkout 重建该快照。单从 HEAD 创建 worktree 不包含脏树改动；编辑前验证内容与快照一致，修复补丁保持独立，不夹带无关工作。
3. 从该 checkout 构建候选二进制，记录精确源码/快照身份和初始门禁结果。复现[检查表 S1–S5](runtime-closure-checks.md)；源码变化后可能已有修复，此时验证而不是回退它。
4. 按包记录 `missing`、`present-needs-verification` 或 `verified`，附源码和测试。紧凑输入、短 ID、artifact 输出、carry/adoption、finish correction 和 hold/park 已是整合输入，不重复实现。

**完成条件：** 另一 agent 无需私人数据库或个人临时目录，即可重建源码并执行合成复现。R1 以该快照为基线。R0 不指定包版本、不安装或授权发布。

### R1：执行事实与授权

移除同链隐式批量结算，使用既有显式观察绑定。旧授权不能跳过派发前的当前意图/限制检查。caller context 仍有效时，provider timeout 与 caller cancellation 分别归因；已接受持久结果和未决效果分别保留。

只读证明检查操作参数，读取 `hostname` 与设置它不同。解释器/Skill 脚本恢复保守处理，路径形状和 basename 不产生可复用权限；本包不开发替代 Skill grant 家族。

修改错误行为，不按整文件或“某 agent 的层”回退。保留的环境/代理/grant 规范化逐项审核。S1–S5 在错误行为上因指定原因失败，在修复后通过，正常对照仍通过，才算完成。

### R2：hold/park 会话保真

复用现有 hold/park/checkpoint。确认实际提问会话仍承载当前 Run 的等待，另一 CLI 心跳不能代替；复用 attachment，不另建 presence 框架。保留现有最长等待、队列压力让出和 daemon drain。

hold 前写入精确 pending-call checkpoint；答复认领和清除 pending binding 保持原子性。写入失败沿用可取消、fail-closed 路径，不假装已释放 worker。迟到或已撤销授权不能派发。

原地与停放答复产生相同持久结果，双 CLI、压力和崩溃 H1–H4 通过后完成。本包不调整默认并发或超时配置。

### R3：已接受状态与精确续接

存储、selector、内核未完成列表和 UI 使用既有 accepted `RunPlanProjection`，以 `(run_id, plan_version)` 标识；请求参数和晚到父事件不能替换较新已接受状态。kernel 保持不依赖数据库和具体工具。

精确 runtime 续接搬运合法进度和来源，不让 Main 再选择自身。人工历史选择保留既有保守导入和 Main 显式采用。范围/条件/相关输入变化或当前失败使对应复用失效，无关历史事实保留。过去构建成功不证明生产现在健康。

P1–P4 比较批准、watcher、provider wait、人工选择后的各消费者，包含重复恢复和旧事件。消除实际重复推导，不另建可写“统一状态”。

2026-10-16 的后续批次将当前 Plan 与收尾事实从同一只读快照选取，注入当前 Run 上下文和已提交的手动接续回执，历史附着另行门控。验证无 parent 的已接受 Plan、当前与历史证据隔离、输入变化、预览不可用及 person 边界，不为获取引用而修改 Plan 状态。

### R4：契约与收尾整合

使用已有紧凑 Plan 输入和完整 accepted 回执。准备阶段反馈保持有界，说明是否派发、具体问题和允许的纠正；完整诊断留在内部。未知字段和近似名称提示不授权自动修补语义。

使用既有 accepted final body 和按序 final Plan/finish，兼容 summary-only 和 native phase；缺少可选 `final_response` 不自动成为输入错误。已证明未派发的格式错可以有界纠正，人拒绝和未知效果不允许盲重试。复用结果提交与 delivery/outbox 事务，不另建 finalizer。

F1–F4 须证明：accepted body 不再生成一次；格式错可在现有限额内修正；保存/投递失败不重复副作用；调查、必要修复及用户接手产生正确结果。下述受限 X3 后续批次处理同范围进度，权限与失败屏障保持。

2026-10-16 的后续批次允许 Main 收尾时按当前 `step_id` 判断条件，避免重抄调用 ID。
运行时绑定当前检查或已接受的采用，保留 Main 的结果、理由及带独立来源的 v2 判断，
拒绝歧义、过期或执行未确认的证据。历史裸 ID 与未采用的旧检查仍不可用，v1 判断语义不变。

所有者 2026-10-16 的继续实施指令授权明确的差量输入：`mode: patch` 保留未提交步骤，
在既有 Plan 事务中按运行时版本展开并校验，完整 `snapshot` 输入保持兼容。
验证完整回执/事件/续接等价、过期或外来 ID、验证和取消要求、并发写入与提交失败。
真实探针显示普通状态推进仍会暂缓工作调用；本次继续实施也覆盖受限 X3：完整 Plan 身份及
Work Unit 不变时允许合法前进，每次仍走中间件，补充输入/失败等保持屏障。Plan/outcome 原子收尾仍独立。

### R5：人工续跑工作集

仅在确有缺口处扩展既有有界 `WorkContinuityHints`：精确候选 Run、相关最近路径和简短失败事实。Main 继续选择目标 Run，验证选择后用 `resume_context` 返回对应工作集。不加入口分类器或 Thread 最近任务路由。

旧 Skill 的身份/版本只作参考，不自动成为生效指令；“过去读过”不证明当前文件内容。原始对话保持端内隔离，预算归现有 selector。不为调用数目标省略必要任务识别和新鲜验证。

M1–M3 区分同工作区/不同工作区 A/B、变化文件、过期 Skill 和陌生人历史后完成。已有 hints 足够时记录验证，不增加重复切片。

## 单独决策和实验

| 项 | 当前状态 | 下一步 |

| X1 推理档位比较 | 实验，未启用 | 明确隔离路由、次数、时间和费用预算，固定二进制，成对比较任务质量与营救次数。 |
| X2 多调用生成 | 实验，未启用 | 探测真实协议行为；未设置 `parallel_tool_calls` 不独自证明单调用原因，执行仍受现有只读并发政策约束。 |

**C1 候选契约：** 只对一条明确、当前可结算 claim 提供复合选项；多个未决项用既有查看/逐项结算。选项不默认，明确本人知道旧效果结果并仅批准当前精确调用一次。在既有 control 事务中重查提供过的选项、活动账号、待答审批和 claim；结算审计、批准决定、既有持久通知意图一起提交，再唤醒执行。精确重复答复返回已记录结果；对象独立变化/过期则拒绝旧复合决定，不部分写入。保留普通 once，派发仍正常检查。启用前通过 C1 检查；普通“是”不结算 claim。

**C2 契约（所有者于 2026-10-15 通过继续实施请求授权）：** 最多两次 judge，共享 15 秒总 deadline，并服从更短 caller/provider 预算；首试最多 10 秒且不超过实际剩余总预算的 80%，第二次只用剩余时间。仅 timeout/transport/empty-response 不可用可重试，合法 deny/escalate 和 caller cancel 不重试。底层 transport 重试计入总预算，迟到答案失效，intent snapshot 变化即停。仍不可用则说明原因转人工，绝不批准。通过 C2 检查，不续期已耗尽的更短预算。此授权不包含 C1 或 X1–X3。

X1 注意：官方 [Qwen 文档](https://docs.qwencloud.com/api-reference/chat/openai-chat) 说明 `high` 映射 `xhigh`，`medium` 是降档，不是修复非法值。记录 wire 配置和 usage；不同时升级代码和改生产推理。自动按步骤调推理、硬超时转后台、通用忽略未知字段均不在本轮修复范围。

## 验证与交付

使用[检查表](runtime-closure-checks.md)中的命令和用例对应。每个变化的消息路径更新既有 eval，或新增生产 wiring 用例和回放证据；纯机制用 Go 测试。WIP 测试缺失属于基线问题，不能声称通过；匹配测试数为零不算成功。

每包交付：源码/快照身份、限定 diff、复用与修改行为、回归/正常对照结果、故障注入和 eval 输出、未测 provider、未决事项。常规实现选择自行判断，不重复索权；政策冲突、不可逆动作和未批准外部实验分别处理。

整合前执行 focused checks 和 fast selfcheck；推送前对同一源码执行完整 selfcheck、所需 race/build/docs 门禁。实际行为变化更新领域文档和翻译，能力或优先级变化才改 STATUS。重复副作用、作用域泄漏、未完成被抹掉或无依据完成均停止推广，回退行为、保留持久历史。

固定清理后基线，度量工作链正确结果、额外营救、调用和契约错误、重复定位/终稿、活跃关键路径及 token 成本；人离线和外部构建时间分列。每周审批数和估算节省比例是观察目标，不作发布门。Go/回放通过不证明跨模型采用或实时性能。

真实模型使用隔离数据/配置和明确预算；真实 IM 验收仍由所有者暂缓。本地安装、生产 daemon 重启、结算生产 claim、发布各自需要用户指令。代码实现和验证可以完成，部署动作仍待处理，交付时分别说明。
